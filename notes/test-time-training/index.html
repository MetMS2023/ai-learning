Fact-checked Learning Notes · Test-Time Training

Test-Time Training：让 LLM 在使用时继续学习

重点不是追逐 SSI 传闻，而是理解 TTT 这条可能改变 LLM 形态的研究路线：它为什么出现、底层是否仍是 Transformer、如何把上下文写进权重，以及怎样避免“越学越笨”。

核心直觉：今天的 LLM 把上下文当作临时草稿纸；TTT 尝试把当前经历变成一次小型训练，让有用信息进入临时权重。

01

TTT 想解决什么问题？

当前 LLM 的主流范式是：先用巨量数据训练出一套固定权重，部署后只做前向计算（推理）。用户给它再长的文档，这些信息通常也只存在于当前上下文或 KV Cache 中，不会变成新的模型能力。

问题 A · 上下文成本

全文注意力越读越慢

Full Attention 每生成一个新 Token，都要查看越来越多的历史 Key/Value。上下文越长，每个新 Token 的成本越高。

问题 B · 滑动窗口遗忘

固定窗口快，但旧内容会离开

Sliding-Window Attention 只看最近一段内容，因此速度稳定；代价是窗口外的 Token 不再可见。

问题 C · 模型不会现场学习

看过不等于学会

普通推理可以临时参考一份长文档，但对话结束后，模型权重没有因这次经历而改变。

TTT-E2E 提出另一种处理长上下文的方式：保留一个便宜的滑动窗口负责最近内容，同时用下一 Token 预测在测试时不断训练模型，把即将离开窗口的信息压缩进临时权重。[3]

长序列不断进入文档、代码或历史记录
滑动窗口直接查看最近 Token
TTT 梯度更新从当前窗口学习
临时权重记忆保留可预测的模式
“压缩”不等于逐字保存。权重更像读完一本书后形成的理解，而不是可以精确翻页的原文。需要原句、数字和出处时，Full Attention、RAG 或外部存储仍然有价值。
02

它的底层还是 Transformer 吗？

答案：在 2025 年 TTT-E2E 论文中，是的。它保留 Transformer 的基本骨架，只把 Full Attention 换成 Sliding-Window Attention，并让最后四分之一 Blocks 中的一部分 MLP 可以在测试时更新。[3]

再认识 Transformer 里的四个基础组件

Embedding · 翻译器

把文字 Token 转成模型能计算的数字向量。它定义了模型最基础的语言坐标。

Attention · 查找器

决定当前 Token 应该从前文哪些 Token 读取信息。这里它只查看最近的滑动窗口。

Normalization · 稳压器

把各层数值维持在稳定尺度，防止信号在深层网络中忽大忽小。

MLP · 加工器

Attention 找到信息以后，MLP 对每个 Token 的内部表示进一步加工。它包含大量可写权重。

TTT-E2E 的实际层级关系

模型入口
Embedding冻结：把 Token 转成向量
前 3/4 Blocks
完全冻结
Sliding-Window Attention + Norm查看最近上下文，权重不改
普通 MLP + Norm继续提供稳定的预训练能力
后 1/4 Blocks
局部可塑
Sliding-Window Attention + Norm仍然冻结
动态 MLP / Prime MLP测试时更新：写入当前上下文
静态普通 MLP测试时冻结：保留稳定计算路径
冻结组件测试时更新固定知识保护路径
静态 MLP 到底“确保”了什么？它只确保自己的参数不被 Inner-loop Optimizer 覆盖：Wstatic,new = Wstatic,old。它在 Meta-training 中与整个模型一起学习，测试时作为固定计算路径继续工作；但它不是全部知识的完整备份，也不能从数学上保证动态更新后模型永远不会变笨。
动态 MLP 与静态 MLP 不是互不相干的平行备份。根据官方代码，后 1/4 Block 先经过动态 MLP，再经过静态普通 MLP。动态 MLP 改变了中间表示，因此静态 MLP 的实际输入和输出也会间接受影响。
残差连接是什么？动态和静态 MLP 都有残差连接：模块不是把输入完全替换掉，而是学习一个“修改量”，再与原输入相加，即输出 = 原输入 + 模块加工结果。这样即使模块学到的修改不够好，原输入仍有一条直接保留的路径。

为什么只更新最后 1/4 Blocks？

更新范围论文实验观察含义
最后 1 层或 1/8长上下文扩展效果不足可写入的动态权重太少，临时记忆容量不足
最后 1/4已经能随上下文长度良好扩展容量与 Backward 成本之间的甜点位
最后 1/2效果与 1/4 大致相当更新更多层没有明显收益，却需要更长的反向传播

因此，“最后 1/4”不是永恒定律，而是论文在当前模型和上下文范围内通过消融实验找到的折中。Embedding、Normalization 和 Attention 都保持冻结，因为论文发现把它们也放进 Inner loop 会使 Outer loop 不稳定。[3]

不要把不同 TTT 论文混成一个架构。2024 年 TTT-Linear/TTT-MLP 把隐藏状态做成独立的小型学习器；2025 年 TTT-E2E 则保留滑动窗口 Transformer，直接更新其中一部分常规 MLP。它们共享“测试时学习”原则，但结构不同。[2]
03

Inner loop 与 Outer loop：现场学习和 Meta-learning

先看两层循环的关系，再分别进入细节：

Outer loop选择并改善共同起点 W₀
Inner loop · 文章 A
W₀ → W₁ᴬ → W₂ᴬ
Inner loop · 文章 B
W₀ → W₁ᴮ → W₂ᴮ
Inner loop · 文章 C
W₀ → W₁ᶜ → W₂ᶜ

Inner loop 做什么？

在一篇文章内部现场学习，回答：“拿到当前文章后，我的动态权重应该怎样变化？”

Outer loop 做什么？

比较大量文章各自完成 Inner loop 后的效果，改善共同的 W₀，让它更善于从新文章中学习。

Outer loop 就是这里所说的 Meta-learning。它不是在部署时学习某一篇文章，而是在研发训练阶段观察大量 Inner loops 的结果，改善所有文章共同使用的初始权重 W₀。
两层循环发生在不同阶段。研发训练阶段：Outer loop 内部反复模拟很多 Inner loops；模型部署后：拿出训练好的 W₀，只在当前文档上运行 Inner loop。文章 A 的临时 W₂ᴬ 不会直接拿去读无关的文章 B。

Inner loop：模型如何一边读取、一边更新权重？

一段已经给出的文本天然带着“标准答案”：前面的 Token 是输入，真实的下一个 Token 就是标签，所以不需要人工标注。

读取一批 Token窗口内已有真实文本
Forward预测每个下一 Token
Loss + Backward计算误差与梯度
更新动态 MLP信息写入临时权重
  1. Forward：模型用当前权重读取这一批 Token，并尝试预测每个下一 Token。
  2. Loss：把预测与真实 Token 比较，得到交叉熵损失。
  3. Backward：计算动态 MLP 中哪些权重导致了预测误差，以及应朝哪个方向改变。
  4. Optimizer step：根据梯度更新动态 MLP，得到更适合当前文档的新状态。
  5. 下一批：模型用新状态继续处理后续 Token。

Outer loop 为什么需要“梯度的梯度”？

普通预训练只优化“固定权重时能否直接预测好”，并没有优化“经过几次 Inner-loop 更新后能否变得更好”。Outer loss 要评价更新后的 W₁、W₂，再一路追溯最初的 W₀，因此精确反传必须穿过 Inner loop 的梯度操作，相当于对梯度再求导。也可以使用一阶近似，省略部分二阶项。[3]

一句话Inner loop 是“学习当前文章”；Outer loop（Meta-learning）是“提前学习怎样从文章中学得更好”。
04

TTT 和 LoRA 是什么关系？

先理解 LoRA

普通 Full Fine-tuning 会直接修改大模型原本的大量权重，训练和保存成本都很高。LoRA（Low-Rank Adaptation，低秩适配）选择冻结原始权重 W，只训练两块小矩阵 A、B，并把它们产生的增量加到原计算上：

基础权重 W冻结，不直接修改
LoRA 小矩阵 A × B只训练少量参数
W + ΔW基础能力 + 任务适配
为什么叫“低秩”？不是直接训练一块巨大的 ΔW，而是用两个窄小矩阵相乘来近似它。这样需要训练和存储的参数少得多。

理解 LoRA 后，再看两者分工：TTT 规定在什么时候、针对什么数据学习；LoRA 只是其中一种低成本修改参数的工具。

概念回答的问题核心做法
TTT什么时候、为什么学习？在测试或使用当前数据时执行学习，让模型适配当前实例
LoRA怎样用更少参数完成更新？冻结原始权重，只训练额外的低秩矩阵

因此，TTT 可以使用 LoRA，也可以不用。例如 ARC、qTTT、Self-Guided TTT 等工作使用 LoRA 来降低每次测试时适配的成本；LoRA 让基础权重保持不动，只保存一小组临时增量。[5]

但 TTT-E2E 最终方案不是 LoRA TTT。论文的对比路线 TTT-KVB 使用过 multi-head MLP + LoRA；最终 TTT-E2E 发现，既然反向传播本身已经很贵，与其更新很多很小的 LoRA 状态，不如只更新最后四分之一 blocks 中较大的常规 MLP。这样获得更大的记忆容量，同时减少需要穿越的网络层数。[3]

LoRA 方案

基础模型完全冻结，临时记忆放在小型低秩增量里。便宜、容易隔离，但可写入容量较小。

TTT-E2E 方案

直接更新少数较大的原生 MLP。每次更新更贵，但动态状态容量更大。

共同目标

限制可塑区域，不让整个模型在一次测试输入上任意漂移。

参数适配不只有 LoRA

适配方式保存什么特点
LoRA两组低秩增量矩阵小巧、易加载，是目前最常见的参数高效适配方式之一
插入式 Adapter插入 Transformer 的小型神经网络模块基础权重冻结，通过额外模块修正模型行为
原生权重 Delta部分原生权重相对 W₀ 的差值无需保存整套模型，但增量可能更大，也更难高效服务
直接更新部分原生权重更新后的 MLP 等参数状态可写容量较大；TTT-E2E 的动态 MLP 属于这一思路
共同点这些参数文件都不是独立模型。它们描述“如何修改某个特定 W₀”，因此必须记录基础模型版本、架构、目标层和 Tokenizer 等兼容信息。
05

如何确保权重变化后，LLM 不会变笨？

先给真实答案：目前没有绝对保证。TTT 的核心难题就是 Plasticity–Stability Trade-off：模型既要能从新上下文学习，又不能破坏预训练能力。论文使用多层防线降低风险，但这仍是开放研究问题。
1

先用 Meta-learning 做准备

训练目标直接评价“经过 TTT 后”的表现，而不是假设任意梯度更新都会有益。

2

只更新 MLP

Embedding、Normalization 和 Attention 保持冻结；论文发现更新它们会造成训练不稳定。

3

只开放最后四分之一 Blocks

限制可修改范围，同时在实验中保留了足够的上下文压缩容量。

4

保留静态普通 MLP

它在 Meta-training 中与模型一起学到稳定能力，测试时权重被冻结。它提供固定计算路径，但不是完整知识备份，也不能保证动态变化完全无害。

5

按 Mini-batch 更新

不是每个 Token 都单独迈一步，而是聚合约 1K Token 的梯度，提高并行度并减少偶然的梯度爆炸。

6

把更新当作会话状态

实验按序列从共同初始化开始，让一次文档的适配不自动污染下一份无关文档。

后续研究进一步说明了风险：如果拿随机、无关的长文本片段做 TTT，模型表现可能下降；选择真正与问题有关的证据片段才可能改善表现。这意味着“学什么”与“怎么学”同样重要。[6]

正确理解TTT-E2E 不是让模型毫无限制地自我修改，而是把可修改范围、学习目标、初始化和更新节奏都提前设计好，让权重更新成为受控的临时记忆机制。
06

为什么 TTT 可能是一种未来范式？

它改变的不是一个小功能，而是“模型什么时候学习”的基本假设。

Context Window把信息放在眼前，模型权重不变；适合精确查看近期内容。
RAG / 外部记忆需要时查笔记；适合事实、出处和可更新知识库。
Test-Time Compute固定模型多想几步；增加搜索，但不会把经历写入参数。
TTT模型在当前任务中真的学习；把上下文压缩进临时权重。

在论文实验中，3B 模型使用标准滑动窗口 Transformer，在 128K 上下文下表现随长度扩展的趋势接近 Full Attention，同时在 H100 上报告了约 2.7× 的推理延迟优势。作者因此把长上下文重新定义为持续学习问题，而不只是不断扩大 Attention 窗口的架构问题。[3]

如果这条路线最终成熟，LLM 可能不再只是“训练好后供人查询的静态知识库”，而会变成“带着一个稳定底座、针对当前经历快速形成临时能力的学习系统”。
但这不是 SSI 技术路线的证明。TTT 与 Ilya Sutskever 公开讨论的部署后学习方向相似，但 SSI 尚未发布技术报告确认采用 TTT。本笔记把 TTT 当作独立研究范式学习，不以传闻作为论据。
07

距离真正成熟，还缺什么？

训练成本

Meta-learning 需要 gradients of gradients。当前 8K 实现比标准预训练慢约 3.4×；一个重要原因是现有高速 FlashAttention 接口不能让 Outer loop 穿过 Inner backward 继续求导。[4]

推理系统

服务用户时不仅要 Forward，还要保存训练激活、Backward、更新权重，并隔离每个会话的动态状态。

安全与数据质量

错误、恶意或无关上下文可能产生有害梯度。模型需要决定哪些内容值得学习、哪些必须忽略。

精确记忆

把经历压进权重意味着有损压缩。精确数字、原句和出处仍需 Attention、RAG 或外部存储。

长期保留

论文重点是单个长序列内的临时学习，不等于已经解决跨用户、跨月份的永久持续学习。

规模验证

主要结果最高到 3B 参数、164B 训练 Token 和 128K 上下文，距离今天最大的生产模型仍有距离。

FlashAttention 是什么？它是高效计算 Transformer Attention 的底层 GPU 算法与调用接口：通过分块计算，避免把巨大的完整 Attention 矩阵反复写入显存。当前接口支持普通 Forward + Backward，但不能让 Backward 本身再被 Outer loop 求导，因此 TTT-E2E 的 Meta-training 暂时无法完整享受它的加速。
08

一个可能的产品形态：分层学习状态

以下是基于现有技术的产品推演，不是 TTT-E2E 论文结论

如果任务内 TTT 成为成熟能力，产品不太可能为每个用户复制一整套基础模型。更现实的结构是：大家共享同一个稳定 W₀，只保存不同时间尺度的小型状态。

共享层
基础模型 W₀
跨用户的通用语言、推理与生成能力
长期个性化
组织 / 用户 / Project 参数
可能采用 LoRA、Adapter 或其他小型权重 Delta
任务内快速学习
TTT 动态状态
当前长任务中不断变化，任务结束后可丢弃或等待巩固
精确记忆
Context / RAG / 文件库
保存原文、数字、出处和可审计的学习记录

“千人千模”更可能是千人千增量

组织、用户或 Project 的个性化参数可以作为小型权重文件保存到云端对象存储、企业私有环境或本地设备；请求到达时，系统共享加载一份 W₀，再按身份加载相应增量。热门增量可缓存在 GPU，低频增量留在 CPU、SSD 或对象存储。

共享 W₀GPU 中只需一份基础权重
加载专属增量组织 / 用户 / Project
当前 Session TTT形成任务内动态状态
结合外部记忆完成个性化任务
参数个性化会带来模型提供商锁定。无论是 LoRA、普通 Adapter 还是原生权重 Delta，都依赖特定 W₀ 的层结构和内部表示。为 Model A 训练的增量通常不能直接安装到 Model B；即使同一家公司的下一代模型，也可能需要重训或蒸馏。
真正可迁移的个人资产，不应只有 Adapter 文件。更值得长期保存的是产生个性化参数的示范、选择与拒绝记录、Project 文件、记忆和个人评估集。Adapter 更像针对某个 W₀ 的“编译产物”；换基础模型时，可以用这些原始学习记录重新生成新 Adapter。

真正理解 TTT，只需抓住这八点

  1. TTT 的目标是让模型从当前测试输入中学习，而不只是在上下文里临时查看它。
  2. TTT-E2E 的底层仍是 Transformer，只是把 Full Attention 换成 Sliding-Window Attention。
  3. 当前文本本身提供下一 Token 标签，模型用 Forward → Loss → Backward 更新动态 MLP。
  4. Meta-learning 负责提前训练出一个“经过测试时更新后会变好”的初始模型。
  5. LoRA 是低成本更新工具，不是 TTT 本身；有些 TTT 用 LoRA，但最终 TTT-E2E 没用。
  6. 论文通过局部更新、冻结大部分网络、保留固定 MLP 路径和 mini-batch 降低遗忘风险，但没有绝对保证。
  7. TTT 的远景是把 LLM 从静态模型变成受控的、会在使用中形成临时能力的学习系统。
  8. 未来个性化可能采用“共享 W₀ + 小型参数增量 + Session TTT + 外部记忆”，但参数增量仍绑定特定基础模型。
