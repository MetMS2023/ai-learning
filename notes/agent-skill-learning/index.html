Agent Skill 应用趋势：从人工编写到可验证的持续进化

今天，专家或 LLM 辅助创建 Skill，以及根据 description 按需调用 Skill，都已经是常规操作。真正的新趋势是：LLM 开始帮助用户持续升级已有 Skill，并用没有参与修改的 Held-out tasks 检查改进是否真的有效。

本文只关注一个核心趋势：Skill 从“被创建、被调用”，发展为“由 LLM 根据经历持续提出改进”。Hermes 展示了 Agent 如何主动修改 Skill；Microsoft SkillOpt 则提供一套更科学的方法，确保修改不是凭感觉，而是有轨迹证据、有更新限制，并经过 Held-out tasks 验证。
01

先理解 Skill：它不是 Prompt 或 Tool

Skill 是一份可按需加载的程序性知识包。最小形式是一份带元数据的 SKILL.md；更完整时还可包含 scripts、references、assets 和模板。开放 Agent Skills 规范要求 description 同时说明“做什么”和“什么时候使用”。[1]

概念主要回答例子
Prompt这一次希望 Agent 完成什么？“请根据这些材料生成本周项目报告。”
ToolAgent 可以执行什么动作？搜索文件、运行代码、调用 API。
Skill遇到某类任务，应该按什么程序完成？如何选择可靠来源、处理冲突、验证结果并按模板输出。

Agent 如何调用 Skill？

发现启动时只看到 name 与 description
匹配当前任务与某项 Skill 相关
加载读取完整 SKILL.md
执行按需使用脚本、参考和模板

可组合

一个任务可同时调用研究、表格处理和报告生成等不同 Skill。

可移植

开放格式让同一个 Skill 有机会在不同兼容 Agent 或 harness 中复用。

节省上下文

先加载少量描述，确定相关后才读取详细内容，这就是 progressive disclosure。

02

真正的趋势：LLM 开始帮助用户升级 Skill

专家手写或让 LLM 辅助创建 Skill，已经是当前做法；Agent 根据 description 判断是否加载某项 Skill，也是标准运行机制。

真正值得关注的趋势只有一个：LLM 不再只负责使用 Skill，也开始根据执行经历帮助用户改进 Skill。

Current SkillAgent 使用当前版本执行任务
Experience成功、失败、Tool 结果和用户纠正
LLM proposes Patch根据证据提出有限修改
Scientific validationHeld-out tasks 变好才采用

较直接的实现

Agent 复盘刚完成的任务，判断哪些办法值得保留，然后主动 Create 或 Patch Skill。Hermes 展示了这种产品机制。

更科学的实现

系统收集多次 Rollout，用受限制的编辑方式产生候选版本，再通过 Held-out tasks 比较决定是否接受。SkillOpt 为同一个趋势增加了方法论和验证纪律。

两者的共同目标

都不是让 LLM 随意重写 Skill，而是让已有 Skill 能根据真实执行经历不断变得更有效。

03

Hermes：Agent 开始管理自己的 Skill

Hermes 和 skill_manage 是什么？

Hermes Agent 是与 OpenClaw 同一大类的开源 Agent harness / runtime：它不是基础模型，而是把模型、Tools、Skills、终端、记忆和会话运行机制组织起来的 Agent 系统。两者属于同一产品类别，但具体架构和功能并不相同。skill_manage 是 Hermes harness 提供的内置技能管理 Tool，不是 LLM 天生自带的能力。模型决定何时调用它，Hermes 负责把 Tool Call 变成对 Skill 文件的实际创建、修改或删除。[2][5]

一句话理解LLM 负责判断“这段经验是否值得保存、应该怎样改”；skill_manage 负责真正操作 Skill 文件。

Hermes 认为什么情况值得保存？

复杂流程成功

Agent 刚完成一个以后可能重复出现的多步骤工作流。

从失败中找到出路

Agent 走过错误路径或遇到工具失败，最终找到可靠办法。

用户明确纠正

用户指出原做法错误，并给出更准确的步骤或判断条件。

skill_manage 可以执行哪些动作？

动作Agent 何时可能调用执行方式
Create第一次形成新的可复用流程Agent 发起 Tool Call，创建完整 SKILL.md。
Patch只需修改一个具体规则或步骤Agent 提供 old/new string；Hermes 官方优先建议这种更新。
Edit原结构已经不适用，需要整体重写Agent 提供新的完整内容并替换旧版本。
Write / remove file需要增加或移除脚本、模板、参考文件Agent 管理 Skill 目录中的支持文件。
DeleteSkill 已过期、错误或被另一项 Skill 取代Agent 请求删除整项 Skill。
动作执行与技能变更审批

这些动作都可由 Agent 主动调用，不需要人工逐项操作，也不会在每轮按固定顺序发生。只有当 Agent 判断需要创建、修改或删除 Skill 时才会调用。默认配置下，Hermes 收到 Tool Call 后直接执行；如果开启“技能变更审批”，修改会先暂存，等待用户查看 Diff 后批准或拒绝。

Hermes 到底从什么内容中学习？

Hermes 文档描述了三种入口：

当前任务中直接保存

Agent 在当前上下文中刚解决了复杂流程、经历失败恢复或收到用户纠正，因此可以立即调用 skill_manage。

Turn 结束后的后台复盘

Hermes 的 background self-improvement review 会在一轮结束后检查刚才的经历，并可建议或暂存 Skill 修改。

用户显式调用 /learn

用户可以让 Hermes 从本地资料、网页、粘贴笔记，或“我们刚才完成的工作流”中制作 Skill。

当前上下文多轮对话、Tool 结果、错误、纠正
Agent 判断是否形成值得复用的程序
skill_manageCreate / Patch / Edit 等
直接应用或暂存取决于技能变更审批设置
多轮对话与用户同意当前多轮对话和 Tool 结果本来就在 Agent 的上下文中，因此可能影响它生成的 Skill；Hermes 文档没有描述面向企业客户的独立 consent 管理或跨用户数据汇总机制。若产品要额外保存、离线分析或跨会话复用用户活动，应明确告知并取得适当同意，同时处理保留期限、敏感信息和访问范围。这是部署层责任，不是 Hermes 已经解决的能力。
04

Microsoft SkillOpt：用 Eval 把 Skill 修改变成受控训练

先简单理解 SkillOpt

SkillOpt 是 Microsoft Research 提出的一种类深度学习、但直接作用于自然语言 Skill 文档的文本空间优化方法。目标 Agent 和底层模型保持冻结，另一个 optimizer model 分析带分数的任务轨迹（rollouts），对工作中的 skill.md 提出有限的增、删、改；候选版本只有在 Held-out tasks 上严格优于当前版本时才会被接受。[3][4]

skill.md 与 best_skill.md

skill.md 是优化过程中持续被编辑的工作文本；best_skill.md 是经过验证后保存的当前最佳版本。它们承担 SKILL.md 的指令角色，但论文和开源实现并没有同时自动优化完整 Agent Skills Package 里的 scripts、references 和 assets；这些附带资源需要保持固定，或由其他机制管理。

Held-out tasks 是什么？

SkillOpt 会把任务分成两部分：一部分用于执行 Rollout、分析问题和修改 Skill；另一部分不参与修改，只用于测试候选 Skill。后一部分就是 Held-out tasks。它们相当于一套 Agent 没有用来“复习和改答案”的独立考题，可以检查修改是否真的能够迁移到新任务。

SkillOpt 的四步主循环

1 · Rollout当前 Skill 执行一批训练任务
2 · Reflect分别分析成功与失败轨迹
3 · Bounded edit合并、去重并限制修改量
4 · Validation gateHeld-out tasks 严格变好才接受
accepted skill → 下一轮

每一步具体发生什么？

步骤输入输出 / 控制
Rollout当前 Skill + 一批训练任务完整任务轨迹：消息、Tool Call、观察、结果和分数。
Reflect成功轨迹与失败轨迹分别找出应保留的有效行为和应修复的重复问题。
Bounded edit多个 add / delete / replace 建议合并、去重、排序，并用编辑预算限制更新幅度。
Validation当前 Skill 与候选 Skill在没有参与编辑的 held-out tasks 上比较；严格改善才接受。

Held-out tasks 为什么是关键？

如果用产生修改的同一批案例评价候选 Skill，系统很容易只记住这些案例。Held-out tasks 没有参与编辑，更能检验改动是否真正迁移。

Current skill在 Held-out tasks 上跑基线
Candidate skill在相同任务和环境中执行
Compare scores成功率、约束、成本等
Accept / reject严格改善才晋升
评测维度要回答的问题
任务成功候选 Skill 是否更稳定地完成目标？
约束遵守是否遵守格式、安全、工具和业务边界？
迁移能力换任务、模型或 Agent harness 后是否仍有帮助？
成本与延迟是否为了少量准确率增加过多 Tool Call 或 Token？
回归修复一个失败时，是否破坏原本能完成的任务？
自动修改还需要科学验证

Hermes 公开实现中的质量控制主要是会话复盘、结构校验、Lint、可选安全扫描和技能变更审批；这些机制帮助 Agent 修改 Skill，但不会自动证明修改提升了任务表现。SkillOpt 用 Held-out tasks 补充了这个性能验证环节。现有公开资料没有显示 Hermes 已集成 SkillOpt 式评测。[6][7]

研究结果边界SkillOpt 报告在 6 个 benchmark、7 个目标模型和 3 种执行方式的 52 个评测单元中达到最好或并列最好，并展示跨模型与跨 harness 迁移。这些是研究 benchmark，不是所有真实应用都能获得同样收益的保证。
