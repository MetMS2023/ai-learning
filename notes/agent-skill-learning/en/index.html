Agent Skill Evolution: From Authored Instructions to Validated Improvement

Today, experts commonly write Skills themselves or ask an LLM to help, while agents load relevant Skills on demand from their descriptions. The more interesting development is that LLMs are beginning to help users improve existing Skills from execution experience—and test those changes on Held-out tasks before adoption.

This note follows one central trend: Skills are moving from things agents merely use to external capabilities that LLMs can improve from experience. Hermes shows how an agent can modify its own Skills; Microsoft SkillOpt proposes a more disciplined approach grounded in Rollouts, bounded edits, and Held-out tasks.
01

First, what is a Skill?

A Skill is a package of procedural knowledge that an agent can load when relevant. At minimum, it contains a metadata-bearing SKILL.md; richer Skills can also include scripts, references, assets, and templates. The open Agent Skills specification requires the description to explain both what the Skill does and when it should be used.[1]

ConceptMain questionExample
PromptWhat should the agent do this time?“Create this week’s project report from these materials.”
ToolWhat action can the agent perform?Search files, run code, or call an API.
SkillWhat procedure should the agent follow for this class of task?How to select reliable sources, resolve conflicts, verify results, and use the correct template.

How does an agent invoke a Skill?

DiscoverSee only names and descriptions at startup

Composable

A task can combine research, spreadsheet-processing, and report-generation Skills.

Portable

An open format gives one Skill a path to reuse across compatible agents and harnesses.

Context-efficient

The agent first sees brief metadata and loads full instructions only when relevant—progressive disclosure.

02

The real trend: LLMs helping users improve Skills

Expert-authored and LLM-assisted Skill creation are already standard approaches. Agents deciding whether to load a Skill from its description is also a normal runtime mechanism.

The emerging change is that LLMs no longer only consume Skills; they can also use execution experience to help improve them.

Current SkillThe agent performs tasks with the current version
ExperienceSuccesses, failures, tool results, and corrections
LLM proposes a PatchProduce bounded changes grounded in evidence
Scientific validationAdopt only if Held-out tasks improve

A direct implementation

An agent reviews a completed task, identifies a reusable lesson, and creates or patches a Skill. Hermes demonstrates this product mechanism.

A more disciplined implementation

The system collects multiple Rollouts, proposes constrained edits, and compares versions on Held-out tasks. SkillOpt adds methodological rigor to the same direction.

The shared objective

The goal is not arbitrary rewriting. It is to make existing Skills more effective through evidence from real execution.

03

Hermes: agents begin managing their own Skills

What are Hermes and skill_manage?

Hermes Agent belongs to the same broad category as OpenClaw: an open-source agent harness and runtime rather than a foundation model. It coordinates models, tools, Skills, terminals, memory, and conversation execution, although its architecture and features differ from OpenClaw. skill_manage is a built-in Skill-management tool supplied by the Hermes harness—not a capability native to the LLM. The model decides when to call it, and Hermes turns that tool call into an actual Skill-file operation.[2][5]

In one sentenceThe LLM decides whether an experience is worth preserving and how the Skill should change; skill_manage performs the file operation.

What experiences does Hermes consider worth saving?

A complex workflow succeeded

The agent completed a multi-step procedure likely to recur.

A failure revealed a working path

The agent hit errors or dead ends and eventually found a reliable solution.

The user corrected the agent

The user identified a bad approach and supplied more accurate steps or conditions.

What can skill_manage do?

ActionWhen the agent might use itExecution
CreateA reusable procedure is recorded for the first timeCreate a complete SKILL.md.
PatchOnly one rule or step needs changingSupply old and new text; Hermes recommends this targeted update.
EditThe existing structure needs a broad rewriteReplace the full document.
Write / remove fileAdd or remove scripts, templates, or referencesManage supporting files within the Skill directory.
DeleteA Skill is obsolete, wrong, or supersededRequest removal of the entire Skill.
Execution and approval

The agent can invoke these actions without a person performing each step, but they do not run as a fixed sequence on every turn. By default, Hermes executes the tool call directly. If Skill change approval is enabled, mutations are staged so the user can review a diff and approve or reject them.

What does Hermes learn from?

Hermes documents three entry points:

Save during the current task

The agent can call skill_manage after a complex success, failure recovery, or user correction in the current context.

Background review after a turn

A background self-improvement review examines the recent experience and may propose or stage a Skill update.

Explicit /learn

The user can ask Hermes to build a Skill from local material, a webpage, pasted notes, or a workflow completed in the conversation.

Conversation data and consentMessages and tool results already present in the agent’s context can influence a generated Skill. Hermes documentation does not describe a separate enterprise consent system or cross-user aggregation mechanism. A product that additionally retains, analyzes offline, or reuses user activity across sessions needs explicit disclosure, appropriate consent, retention controls, sensitive-data handling, and access boundaries.
04

Microsoft SkillOpt: training Skill changes with evaluation

SkillOpt in brief

SkillOpt is a Microsoft Research text-space optimization method that resembles deep-learning discipline while operating directly on a natural-language Skill document. The target agent and model remain frozen. A separate optimizer model analyzes scored task trajectories—Rollouts—and proposes bounded additions, deletions, and replacements to the working skill.md. A candidate is accepted only when it strictly outperforms the current version on Held-out tasks.[3][4]

skill.md and best_skill.md

skill.md is the working text edited during optimization; best_skill.md is the best validated version exported so far. These files can play the instructional role of SKILL.md, but the reported implementation does not jointly optimize scripts, references, assets, or other files in a complete Agent Skills package.

What are Held-out tasks?

SkillOpt divides tasks into two groups. One group produces Rollouts and informs Skill edits. The other group does not participate in editing and is used only to test candidates. Those independent test cases are Held-out tasks: they reveal whether an edit transfers beyond the examples that produced it.

SkillOpt’s four core actions

1 · RolloutRun training tasks with the current Skill
2 · ReflectAnalyze successful and failed trajectories
3 · Bounded editMerge, rank, and limit changes
4 · Validation gateAccept only if Held-out tasks improve
accepted skill → next round

What happens at each step?

StepInputOutput or control
RolloutCurrent Skill plus training tasksTrajectories containing messages, tool calls, observations, outcomes, and scores.
ReflectSuccessful and failed trajectoriesIdentify behavior to preserve and recurring problems to correct.
Bounded editProposed add, delete, and replace operationsMerge, deduplicate, rank, and clip edits under a budget.
ValidationCurrent and candidate SkillsCompare them on Held-out tasks; accept only a strict improvement.

Why are Held-out tasks essential?

Evaluating a candidate on the same examples that produced its edits encourages overfitting. Held-out tasks did not participate in editing, so they better test whether the change transfers.

Automatic editing still requires performance validation

Hermes publicly documents conversation review, structural validation, linting, optional security scanning, and Skill-change approval. These mechanisms help manage Skill updates but do not prove that an edit improves task performance. SkillOpt adds a Held-out-task performance gate. Public materials do not show Hermes integrating SkillOpt-style evaluation.[6][7]

Evidence boundarySkillOpt reports best or tied-best results across 52 evaluated cells spanning six benchmarks, seven target models, and three execution modes, with transfer across models and harnesses. These are research benchmarks—not a guarantee that every production task will obtain the same improvement.
