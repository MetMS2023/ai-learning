大模型训练、RL在线推理与训推一体化

这份笔记梳理大模型从预训练、后训练到上线服务的完整生命周期，重点理解在线强化学习为什么需要推理、PPO/GRPO 位于哪个环节，以及“训推一体化”究竟解决什么问题。

核心认识：大模型发布后的生产推理通常使用冻结权重；但在在线 RL 训练期间，模型也必须不断执行推理来生成 Rollout，因此推理成为训练闭环的一部分。

01

大模型从训练到上线的生命周期

先建立全局地图。为了使用认知度更高的词，这份笔记把后训练概括为 SFT、RLHF 和 RL；但三者并不是互斥、边界绝对清晰的三个盒子。

预训练学习语言与知识模式
后训练SFT · RLHF · RL
评估与发布选定 checkpoint
生产推理SGLang / vLLM
后训练目标：让模型更会回答、更符合要求、更会解决任务
SFT · 监督微调给模型看“标准答案”，让它模仿示范。
RLHF · 人类反馈对齐利用人类偏好信号塑造模型行为；经典做法可包含奖励模型与 PPO。
RL · 强化学习模型先尝试，再根据规则、验证器、奖励模型或环境反馈更新。
严谨性提醒RLHF 通常会使用 RL，所以两者不是完全平行、互不相干的阶段。这里分别列出，是为了方便入门理解：RLHF 强调根据人类偏好调整模型；RL 强调模型尝试、获得奖励、再更新权重。InstructGPT 的经典 RLHF 流程就是 SFT → 奖励模型 → PPO。[1]
02

预训练、SFT 和 RL 分别解决什么问题？

2.1 预训练：先获得广泛的基础能力

对 GPT 这类自回归语言模型而言，预训练通常通过预测下一个 Token，从大量文本、代码等数据中学习语言模式、知识关联和可迁移的表示。它并不是把百科逐条写入数据库，而是把统计规律沉淀进模型参数。

我的理解预训练让模型“读过很多内容、学会语言规律”，但不保证它天然会遵循指令、按格式回答或符合人类偏好。

2.2 SFT：给标准答案，让模型模仿

SFT（监督微调）使用事先准备好的“问题 → 理想回答”样本。训练时比较模型预测和标准答案，再通过反向传播调整权重。

固定示范数据问题 + 理想回答
模型模仿回答预测下一个 Token
计算误差预测与答案的差距
更新权重把正确模式学进去

2.3 在线 RL：没有完整标准过程，让模型先尝试

在线 RL 会让当前模型针对问题生成回答或行动过程，称为 Rollout（采样轨迹）；系统再根据结果给出奖励，并调整模型。

当前模型此刻的能力版本
生成 Rollout答案、代码或工具轨迹
验证与奖励对错、测试或偏好分
更新模型权重强化更可能得高分的行为
最重要的基础概念“更新策略模型”在这里通常就是更新这个语言模型的可训练权重。在 RL 术语里，Policy（策略）指“模型面对输入时，以什么概率生成哪些 Token 或动作”。权重改变后，输出概率随之改变，所以我们说策略被更新。若只训练 LoRA，则变化的是适配器参数，而不是全部基础权重。
Rollout 与普通推理有什么关系？生成文本的前向计算相同，但 RL 还要保存生成概率、奖励等训练信息，并在后面执行反向传播。面向用户的生产推理通常只生成答案，不在每次请求后反向传播。[2]
方法模型拿到什么模型怎么学
预训练海量文本、代码等数据学习预测下一个 Token
SFT问题和理想回答模仿标准示范
在线 RL问题、自己生成的 Rollout 和奖励提高高奖励行为的概率
03

RL 需要在线推理

“在线”不是指连接互联网。它表示：模型在训练过程中不断产生新的回答或行动，用这些新经验获得反馈，再继续更新权重。

模型 θ₀生成第 1 批经验
根据奖励更新权重得到 θ₁
模型 θ₁生成第 2 批经验
继续更新权重得到 θ₂……
用学生做题来理解学生每学会一点，就用当前的新水平做下一批题；新答案得到新反馈，再继续改变学生。模型也是如此：θ₀ 生成经验并更新成 θ₁，θ₁ 再生成下一批经验。负责把奖励转化成权重更新的典型算法，就是下面的 PPO 和 GRPO。
04

PPO 和 GRPO：把奖励变成权重更新

模型已经生成了 Rollout，也拿到了奖励。下一步的问题是：应该鼓励哪些回答，以及权重应该改变多少？PPO 和 GRPO 就是处理这个环节的两种算法。

生成回答模型进行尝试
获得奖励判断回答好不好
PPO / GRPO把奖励转成训练信号
更新权重得到新模型

两者最核心的区别：怎样判断一个回答“相对有多好”？

对比PPOGRPO
基本做法训练一个额外的 Critic，估计这个回答原本预期能得多少分让模型对同一道题生成一组回答，直接在组内比较分数
如何理解实际得分比 Critic 的预期更好，就鼓励这次回答得分高于同组平均水平，就鼓励这次回答
额外成本需要训练和保存 Critic不需要独立 Critic，但每道题要生成多个回答
共同点都需要奖励信号，并通过反向传播更新语言模型权重

PPO：与“预期分”比较

例如 Critic 预期能得 60 分，实际得到 85 分。这次表现比预期好，模型就更应该保留这种回答方式。

GRPO：与“同组分”比较

同一道题生成四个答案，平均 60 分，其中一个得到 90 分。这个答案高于同组水平，因此得到鼓励。

最后都做同一件事

把比较结果变成训练信号，通过反向传播调整模型权重，从 θ₁ 更新到 θ₂。

严格来说，PPO 还会限制每次更新不要过大；GRPO 的原始设计也包含稳定训练的约束。但这些数学细节不影响这里的核心理解。[2][3]

两者都离不开奖励数学题可以验证最终答案，代码可以运行测试；更主观的任务可能使用 Reward Model。GRPO 去掉的是独立 Critic，不是去掉评分环节。
05

训推一体化：让“生成”和“训练”高效接力

现在把前四节串起来：模型先通过推理生成 Rollout，PPO/GRPO 再通过训练更新权重；新权重又要交回推理端生成下一批 Rollout。这个循环会反复运行成百上千次。

推理引擎批量生成 Rollout
环境与工具执行代码、搜索或行动
奖励与验证判断结果好不好
训练器PPO / GRPO 更新权重
为什么不直接用普通训练程序？普通 SFT 可以事先准备好数据后连续训练。在线 RL 的训练数据却由模型现场生成，而且权重不断变化，所以系统必须反复完成“生成 → 评分 → 更新 → 同步新权重”。

这就是“训推一体化”要解决的问题：不是把训练和推理混成同一件事，而是让两者顺畅接力：

推理端交出 Rollout

把模型刚生成的回答、行动过程和相关训练信息交给评分与训练环节。

训练端交回新权重

PPO/GRPO 根据奖励更新模型，再把新权重交回推理端开始下一轮。

系统减少中间等待

尽量降低数据搬运、重复加载和 GPU 空闲，让闭环运行得更快。

训练和推理可以使用同一批 GPU 轮流工作，也可以放在不同 GPU 上；这是工程部署选择，不影响对核心流程的理解。HybridFlow 和 vLLM 的官方设计都支持训练与生成之间的协同和权重同步。[4][5]

06

训练结束：从“学习模式”切换到“服务模式”

当团队认为某一轮训练已经达到目标，就会从多个 checkpoint 中选出候选版本，做能力、安全与稳定性评估，再把选定的权重快照交给生产推理系统。

完成训练停止本轮权重更新
评估 checkpoint能力 · 安全 · 稳定性
确定权重快照选定正式模型版本
推理框架部署SGLang / vLLM
服务用户只做前向生成

推理框架接手以后做什么？

SGLang、vLLM 等推理框架的目标不再是“把模型教得更聪明”，而是“用既定权重更快、更便宜、更稳定地回答更多请求”。它们负责请求调度、连续批处理、KV Cache、显存管理、模型并行和高效算子；是否启用 Prefill/Decode 分离、低精度或跨节点部署取决于实际配置。

对比RL 训练中的 Rollout 推理发布后的生产推理
目的生成训练经验，让模型继续学习稳定服务真实用户
之后是否反向传播是，PPO/GRPO 会更新权重普通请求后通常不会
权重状态每轮或每若干轮发生变化使用选定快照，直到显式更新
核心系统指标生成和训练效率延迟、吞吐、成本和可靠性
完整链条SFT/RLHF/RL 负责在发布前后训练阶段改变模型；在线 RL 借助推理引擎生成 Rollout；PPO/GRPO 把奖励转成权重更新；训推一体化让这套循环高效运行；训练结束后，选定的权重快照再交给 SGLang/vLLM 做生产服务。

六点学习总结

  1. 大模型先经历预训练和后训练；后训练常用 SFT、RLHF、RL 等概念描述，但它们可能重叠。
  2. SFT 模仿标准答案；在线 RL 则让模型先生成 Rollout，再根据奖励更新权重。
  3. PPO/GRPO 所说的“更新模型”，就是通过训练调整模型的可训练权重。
  4. PPO 和 GRPO 位于“获得奖励 → 更新权重”之间，负责计算权重该怎样改变。
  5. 训推一体化连接“生成 Rollout”和“训练更新”，既可以共置，也可以分离部署。
  6. 训练结束后，选定的权重快照交给 SGLang、vLLM 等推理框架服务用户。
