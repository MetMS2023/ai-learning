Looped Transformer 与 Latent Reasoning：Mythos 和 Astra 可能都在用的架构

Claude Mythos 发布后，OpenMythos 曾推测它可能采用 Looped Transformer；几个月后，Astra 又被可信媒体报道使用有限 Recurrent Depth。两次信号都指向同一个正在升温的方向：模型不只靠生成更长的 Chain-of-Thought 获得更多计算，也可能在连续隐藏状态中反复精炼表示。本文从这两个案例出发，梳理 Looped Transformer、Latent Reasoning 与 Test-Time Reasoning 的关系。

阅读主线：先看 Mythos 与 Astra 为什么都被关联到 Recurrent Depth，再理解 Test-Time Reasoning 的三条路径。Looped / Recurrent-depth Transformer 并不等同于全部 Latent Reasoning；它具体属于 Latent Reasoning 中沿网络深度重复计算的 Vertical latent recurrence。
01

从 Mythos 架构猜想到 Astra 架构报道

2026 年 4 月 Claude Mythos 发布后，Anthropic 没有公开具体架构。社区项目 OpenMythos 随后提出一种理论重构：Mythos 可能采用 Recurrent-depth / Looped Transformer，在同一组 Transformer 层上进行多轮隐藏计算。OpenMythos 明确声明，这只是根据公开研究构建的独立假设，与 Anthropic 无关；Anthropic 的 Mythos System Card 也没有确认该架构。[2][3]

2026 年 9 月，TechCrunch 转述 The Information 的报道：OpenAI 的 Astra 模型使用有限的 recurrent depth，也被报道为 “opaque recurrence”。OpenAI 首席科学家 Jakub Pachocki 的公开回应没有明确否认 recurrence，而是强调计算图深度仍受约束，并希望保留 Chain-of-Thought monitorability。OpenAI 同样尚未发布完整架构文档。[1]

2026 · 04Mythos / OpenMythos社区把 Recurrent-depth 猜想写成代码；它是架构假设，不是 Anthropic 实现证据。
2026 · 09Astra 报道可信媒体明确报道有限 Recurrent Depth；具体层、循环数和停止方式未公开。
引出两个概念Looped Transformer + Latent Reasoning前者描述架构，后者描述隐藏空间中的计算范式。

两个概念如何区分？

概念它描述什么彼此关系
Looped / Recurrent-depth Transformer一种架构：同一 Transformer Block 或 Core 在隐藏状态上重复运行。它是实现 Latent Reasoning 的一种方式。
Latent Reasoning一种计算范式：中间推理主要发生在连续 Hidden states，而非全部变成语言 Token。范围更大，还包括 Coconut、CODI 等 Horizontal latent recurrence。
Test-Time Reasoning / Compute模型收到问题后、给出答案前额外投入计算的总集合。包括 Explicit、Latent 和额外非语义 Token 三条主要路径。
02

Test-Time Reasoning 的三条主要计算路径

Test-Time Reasoning 的共同目标，是在模型权重已经固定的情况下，为当前问题分配更多计算。三条路线的主要区别，是额外计算发生在哪里、是否产生新的 Token，以及中间过程能否被人读懂。

Test-Time Reasoning
/ Test-Time Compute
1 · Explicit Reasoning
可见语言 Token
Chain-of-Thought、Long CoT、Search、Self-consistency
2 · Latent Reasoning
连续 Hidden states
Vertical: Looped Transformer、Huginn、Fixed-point Reasoner
Horizontal: Coconut、CODI、Continuous Thoughts
3 · Extra non-semantic tokens
额外 Token 位置，但不要求承载自然语言
Pause tokens、Filler tokens、Learned planning tokens
Looped Transformer 在哪里？

它属于第 2 条 Latent Reasoning 下的 Vertical latent recurrence：在网络深度方向重复使用共享 Core，增加隐藏空间中的顺序计算。

路径额外计算载体是否新增 Token 位置中间过程可读性
Explicit Reasoning自然语言推理 Token是相对最高，但不保证忠实
Vertical latent recurrence同一表示经过多轮共享层通常否低
Horizontal latent recurrence连续 Hidden state 作为下一思维位置增加潜在位置，不一定增加可见 Token低
Non-semantic token computePause / Filler / Learned embeddings是Token 本身通常无可读语义

下面从最熟悉的 Explicit CoT 开始，再进入两类 Latent recurrence，最后看介于两者之间的非语义 Token 路线。

03

Explicit Reasoning：用可见 Token 展开计算

Explicit Reasoning 把中间步骤写成语言。模型每生成一个新的思维 Token，都要让该 Token 经过整套网络，再将它加入上下文，用于生成下一步。

Prompt问题与上下文
Thought Token 1“先计算 A”
Thought Token 2“再检查 B”
Answer最终输出

Chain-of-Thought

生成一条逐步推理轨迹，适合数学、代码和可分解任务。

Long CoT

通过更长的显式推理分配更多 Test-time compute，但延迟和 Token 成本更高。

Search / Self-consistency

生成多条候选推理路径，再投票、评分或用 Verifier 选择结果。

它为什么有效？

自回归模型每多生成一个 Token，就多执行一次完整网络 Forward，并把中间结果外化为后续输入。因此 CoT 不只是“解释答案”，也是为模型增加序列计算步骤的一种方式。

优势代价与限制
易于提示、训练和部署；中间文字可供人或 Monitor 阅读；可自然接入工具调用和 Verifier。增加生成时间、输出 Token、Context 占用与 KV Cache；语言表达可能迫使模型过早选择单一路径。
适合需要沟通、审计和可复现步骤的任务。可见 CoT 并不保证忠实反映真正内部计算，模型也可能写出事后合理化解释。
Explicit 路线的长期位置即使 Latent Reasoning 变强，显式推理仍很可能保留在需要沟通、审计、工具执行和结果验证的环节。
04

Latent Reasoning：在连续隐藏表示中继续计算

Latent Reasoning 不要求每一步先被转换为自然语言 Token。连续向量可以保留比单个离散词更丰富的状态，并可能同时携带多个候选方向。当前主要分为 Vertical 与 Horizontal 两支。

Vertical latent recurrence：沿网络深度循环

普通 Transformer 通常堆叠许多结构相似、但参数彼此独立的 Block。每个 Block 都包含 Attention、MLP、Normalization 与 Residual path，但第 1 层使用参数 θ₁，第 2 层使用 θ₂，直到第 N 层 θₙ。隐藏表示按固定顺序通过一次后进入输出层。

普通 Transformer：固定独立深度

Token Embedding把 Token 变成向量
Transformer Block 1 · θ₁Attention + MLP
Transformer Block 2 · θ₂不同参数
Transformer Block 3 · θ₃不同参数
… Block N · θₙ每层通常各自学习功能
LM Head映射为 Next-token logits

参数深度和计算深度大致绑定：N 组独立 Block，执行 N 次 Block 计算。

Recurrent Depth：专用两端 + 共享核心

Token Embedding把 Token 变成向量
Prelude · θₚ专用输入处理层
Shared Core · θ꜀ · Pass 1更新 Hidden state
Shared Core · 同一 θ꜀ · Pass 2再次精炼
Shared Core · 同一 θ꜀ · Pass R按预算继续循环
↻ SAME WEIGHTS
Coda · θₒ专用输出处理层
LM Head映射为 Next-token logits

Unique parameters 主要由 Prelude、一个 Core 与 Coda 决定；实际计算深度还取决于循环次数 R。

Prelude、Shared Core 和 Coda

Prelude

循环前的非共享输入层，把 Embedding 与上下文整理为适合反复推理的初始 Hidden state。

Shared Recurrent Core

重复调用的 Transformer Block 或 Block group。每轮用同一组权重继续更新表示；部分设计会再次注入原始输入。

Coda

循环后的非共享输出层，把多轮精炼后的 Hidden state 转换为适合 LM Head 的表示。

为什么保留 Prelude 和 Coda？输入理解、反复推理与答案形成可能需要不同功能。两端保留专业化，中间 Core 负责可重复计算。具体论文的层数、Input injection、Gating 和停止机制并不完全相同。
h₀ = Prelude(x)　　hᵣ = Core(hᵣ₋₁, x)　　output = Coda(hᴿ)

互动｜参数深度与计算深度可以分开

Prelude 和 Coda 各 2 层，中间 Core 有若干物理层。增加 R 不增加 Unique Core weights，却会增加实际层应用次数。

Huginn 展示了真实 3.5B 语言模型中的 Recurrent Depth；长度泛化研究则表明，迭代任务可能利用更多循环处理超出训练长度的问题。[7][5]

Universal Transformer 的位置它是共享深度与 Adaptive Computation 的重要源流，但最初重点不完全等于今天的 Latent Reasoning。Huginn 等工作才更明确地把 Recurrent Depth 解释为 Test-time latent compute。

Horizontal latent recurrence：沿潜在思维位置推进

Horizontal 路线不一定重复同一个 Transformer Core。它更像把“思维序列”从自然语言 Token 换成一串连续 Hidden states：当前潜在状态经过模型处理后，成为下一潜在位置的输入，直到模型切回语言空间并生成答案。

Prompt→h₁→h₂→h₃→Answer

Continuous Thoughts 是什么？

普通 CoT 的每一步必须先选出一个离散 Token；Continuous Thought 则直接使用高维向量作为中间状态。一个向量不必对应一句可翻译的话，理论上可以同时保留多个候选方向、置信度与未决信息，下一步再继续演化。

Coconut

Training Large Language Models to Reason in a Continuous Latent Space 将某一步最后的 Hidden state 直接反馈为下一 Continuous Thought。训练采用逐阶段 Curriculum：先使用显式 CoT，再逐步用连续状态替代中间语言步骤。论文在规划型任务中观察到类似并行保留多条候选路径的行为。[8]

CODI

Compressing Chain-of-Thought into Continuous Space via Self-Distillation 用模型自身的显式 CoT 作为教师，让潜在思维在表示和最终答案上模仿显式推理。部署时可减少可见推理 Token，但仍依赖训练阶段的语言推理监督。[9]

Continuous Thoughts

这是更泛化的概念，而不是单一模型名：中间计算由连续表示承载，可以由 Hidden-state feedback、自蒸馏、压缩或其他机制实现。

比较Vertical recurrenceHorizontal recurrence
重复发生在哪里？同一 Hidden sequence 在网络深度中反复经过共享 Core。一个潜在思维状态接着另一个潜在状态，沿“思维位置”推进。
典型例子Looped Transformer、Huginn、Fixed-point ReasonerCoconut、CODI、Continuous Thoughts
主要优势参数深度与计算深度解耦，便于把循环次数作为计算预算。可能保留更丰富的候选信息，减少每一步都翻译成语言的瓶颈。
主要困难串行延迟、稳定性、何时停止、Weight sharing 限制层专业化。如何训练、如何监督、何时退出潜在空间，以及潜在轨迹是否真的因果有效。
不要把 Continuous Thought 当成“脑内句子”潜在状态可能可以被部分解码，但它不一定对应完整、逐步、忠实的自然语言推理。性能提升、可解码模式与真正的因果推理是三个不同问题。
05

Extra Non-semantic Token Compute：增加位置，但不写自然语言

第三条路径仍向序列加入额外 Token，因此模型会执行更多 Forward；但这些 Token 不要求表示“先算 A”之类可读句子。

Pause Tokens

在回答前插入训练过的 Pause embedding，为模型提供额外计算位置。

Filler Tokens

用没有任务语义的占位 Token 延长计算序列，测试“纯额外计算”是否有帮助。

Learned Planning Tokens

学习专门用于计划或压缩中间状态的 Token，但不要求对应人类语言。

Prompt问题
[Pause]额外位置
[Pause]额外位置
Answer答案
与 Explicit CoT 的区别与 Latent recurrence 的区别
仍增加 Token 位置，但 Token 不必携带可读推理语义。不一定把 Hidden state 反馈为下一 Continuous Thought，也不一定共享层做 Depth loops。
实现更接近现有自回归基础设施。KV Cache 和序列长度仍随额外位置增加。
为什么单列为第三支？它既不像显式 CoT 那样通过语言沟通，也不完全等于 Hidden-state recurrence。把它单独列出，能避免把“不可读 Token”和“没有 Token 的潜在计算”混为一谈。
06

三条分支与研究路线如何演进？

这些路线围绕同一个问题逐步分化：如何在不扩大模型权重的前提下，让推理时计算更充分？下表按时间先后排列。

2023–2024Pause Tokens、Quiet-STaRNon-semantic Token / Explicit Reasoning额外序列位置与内部 Rationale 可以增加推理时计算。

Monitorability 为什么成为争议中心？

显式 CoT 至少提供可读取的语言通道；Latent computation 则更难被传统文字 Monitor 覆盖。但显式 CoT 从来不是内部机制的完整转录，可读也不等于忠实。

能力风险

如果 Latent compute 成为容易扩大的 Runtime dial，实验室可能为能力牺牲 Monitorability。

证据限制

Hidden state 可被 Probe 解码，或 PCA 呈现漂亮轨迹，并不证明该表示因果性地主导答案。

合理治理

测量 Monitorability，同时结合行为评测、Interpretability、Verifier、工具权限和审计。

Latent Chain-of-Thought? 对 Huginn 的分析没有发现稳定、清晰、逐步的潜在 CoT；Chain-of-Thought Monitorability 则强调 CoT 监控不完美但仍有价值，且可能被架构与训练选择侵蚀。[12][13]

08

未来路线判断：竞争、互补与融合

Explicit Reasoning

判断：长期保留。它最适合沟通、审计、工具调用、程序执行与 Verifier；但会减少无意义冗长，更多由模型按需触发。

Vertical Latent Recurrence

判断：最可能成为核心架构组件。它提供参数量之外的计算深度 Scaling 轴，但必须解决稳定性、Adaptive halting 和 Serving latency。

Horizontal Latent Recurrence

判断：规划与搜索任务潜力大。连续状态可能保留多候选方向，但训练监督、可解释性和 Frontier-scale 证据仍不足。

Non-semantic Tokens

判断：实用的过渡与补充路线。容易兼容现有 Decoder，但可能受 KV Cache 和序列成本限制。

问题当前判断
Looped Transformer 属于哪条路线？Latent Reasoning → Vertical latent recurrence。
它和 Latent Reasoning 同义吗？不是；Latent Reasoning 还包括 Horizontal recurrence 等方法。
Explicit Reasoning 是 Latent 的子类吗？不是；两者是 Test-Time Reasoning 下的并列分支。
哪个分支会胜出？更可能是混合：Latent 负责内部计算，Explicit 负责沟通与验证，Tools 负责精确执行。
Recurrent Depth 会替代普通 Transformer 吗？更可能部分融入，而不是整体替换。
Astra 是否证明路线已成熟？没有；它只是 Frontier Lab 可能开始产品化有限 recurrence 的可信信号。
最终认识真正的新趋势不是单一架构取代 Transformer，而是 Test-time computation 从“只生成更多文字 Token”，扩展为一个异构系统：可见推理、隐藏状态循环、非语义计算位置、Search、Verifier 与 Tools 按任务动态组合。
